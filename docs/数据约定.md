# 盲审材料隔离数据约定

原件片段采用 Unicode 码点坐标，区间左闭右开；原文与遮盖位置的版本号一起保存。

data/example.json 中的记录均为虚构业务样例。字段名称与字段类型由 contracts 中的数据结构描述。原始记录按来源提供的顺序读取，字段值不在读取时改写。

## 遮盖区间

遮盖策略由区间列表构成，每条区间是一个对象：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `field` | 字符串 | 遮盖目标：`text`（正文）、`attachment_filename`（附件文件名）、`attachment_description`（附件说明） |
| `start` / `end` | 整数 | Unicode 码点坐标，左闭右开，`0 <= start < end <= 目标长度` |
| `attachment_id` | 字符串 | 目标为附件时必填，须对应当前版本的附件编号 |
| `label` | 字符串 | 可选备注（如"当事人姓名"），最长 128 码点 |

- 一次遮盖可以覆盖多个区间；重叠或相邻的区间合并为一段，统一替换为
  固定占位符 `〔已遮盖〕`，占位符长度与原文无关，不外泄原文长度。
- 区间边界落在字符簇内部时（组合字符、ZWJ 表情序列、肤色修饰符、
  旗帜序列、CRLF 等），自动外扩到完整字符簇，中文与表情都不会被
  切出半个字符。
- 策略按当前原件版本校验；原件补充后若旧策略越界或附件缺失，生成
  副本会被拒绝（409），需先更新策略。

## 编号与容量

- `document_id`：`[A-Za-z0-9][A-Za-z0-9._-]{0,127}`，由接收窗口登记时指定。
- 附件编号：同字符集，最长 64，缺省按 `att-1`、`att-2` 顺延。
- 副本号：`CP-` 前缀的随机十六进制；下载令牌为 256 位随机值，二者均
  不含任何提交者信息。
- 容量上限：正文 200000 码点，附件 100 个，文件名 500 码点，附件说明
  5000 码点，单条策略 2000 条区间，联系方式 500 码点。

## 版本与失效

- 原件每次补充产生新 `revision`；策略每次更新产生新 `policy_version`。
- 副本记录生成时的 `(revision, policy_version)`，随状态一起落盘，
  重启后仍可追查副本对应的原件版本。
- 原件补充或策略更新时，尚未领取的旧副本立即失效；已领取的副本
  （`claimed_at` 非空）保持可取阅。

## 状态文件

运行状态保存在 `BLIND_STATE_PATH`（默认 `data/state.json`），原子写
入，包含五部分：

- `documents`：原件各版本正文与附件、各版本遮盖策略（仅保管员可见）；
- `contacts`：当事人自愿提供的回访方式（仅接收窗口可见，与其余数据
  分开保存）；
- `copies`：去标识副本的内容、状态、复核签名与领取时间；
- `tokens`：下载令牌到副本号的映射；
- `audit`：访问记录，只写动作、目标编号与版本号，绝不写入联系方式
  或原文内容。
